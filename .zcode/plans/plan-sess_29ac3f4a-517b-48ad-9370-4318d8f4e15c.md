# CI/CD for oca-medical-site: create the (missing) GitHub Pages workflow + verified package fixes

## Context

This repo is a fresh Astro 7 static-site delivery where **only README.md is committed**. The README references a "bundled" `.github/workflows/deploy.yml` that **does not exist** — so this task is really *creating* the CI/CD pipeline with the pasted CI-optimization recommendations applied, after fact-checking them:

- ❌ **TypeScript 7 recommendation is reversed**: `typescript@7.0.2` exists on npm, but installed `@astrojs/check@0.9.12` peer-requires `typescript ^5.0.0 || ^6.0.0`, and `astro check` cannot run on TS7 yet ([Astro roadmap #1321](https://github.com/withastro/roadmap/discussions/1321)). Revert to `^5.9.3` or `npm install` breaks.
- ✅ `@types/node@26.6.6` is valid (it's the current `latest` tag on npm; the "26.6.6 isn't real" claim referred to the Node runtime, not the types package).
- ✅ `build.concurrency` is supported by installed Astro 7.4.12 (default `1`; Astro's own docs caution the default is usually right — including it anyway per the recommendation, easily reverted).
- ✅ No CI exists, no lockfile exists, and `.gitignore` only contains `node_modules` (so `.astro/` would get committed on the first real commit).
- **User decisions**: Node **26 LTS** (engines stays `>=26 <27`); **Bun** as package manager. Per the pasted analysis's own Risk-1 mitigation, CI installs with Bun but runs Astro on **Node 26** (`bun run` would execute Astro under Bun's runtime — avoid for `astro check` reliability).

## Changes

### 1. `package.json`
- `"typescript": "^7.0.2"` → `"^5.9.3"` (matches installed 5.9.3; required by `@astrojs/check` peer range).
- Move all 12 packages from `dependencies` → `devDependencies` (pure static site — everything is build-time; drop the empty `dependencies` field).
- Keep `engines.node: ">=26 <27"` and `@types/node: ^26.6.6` as-is.
- **No `packageManager` field** — Bun's version is pinned via the workflow input instead (avoids corepack strict-mode conflicts when `npm run` is used as the script runner in CI).

### 2. Generate + commit `bun.lock`
Run `bun install` locally (Bun 1.4.4 is current) to produce the text-format `bun.lock`; commit it. `bun install --frozen-lockfile` in CI requires it. No `package-lock.json` exists, so nothing to remove.

### 3. `astro.config.mjs`
Add:
```js
build: { concurrency: 4 },
```

### 4. New `.github/workflows/deploy.yml` (the file the README already promises)

Hand-rolled rather than `withastro/action@v6` because that action **skips `astro check` and the smoke test**, which this project's README treats as required gates.

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    timeout-minutes: 10
    env:
      SITE_URL: ${{ vars.SITE_URL || format('https://{0}.github.io', github.repository_owner) }}
      BASE_PATH: ${{ vars.BASE_PATH || format('/{0}', github.event.repository.name) }}
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7        # Node 26 runs Astro/check/smoke
        with:
          node-version: 26
      - uses: oven-sh/setup-bun@v2.2.0     # Bun only installs dependencies
        with:
          bun-version: 1.4.4
      - name: Cache Bun packages
        uses: actions/cache@v4
        with:
          path: ~/.bun/install/cache
          key: ${{ runner.os }}-bun-${{ hashFiles('**/bun.lock') }}
          restore-keys: ${{ runner.os }}-bun-
      - name: Cache Astro build artifacts
        uses: actions/cache@v4
        with:
          path: node_modules/.astro
          key: astro-${{ runner.os }}-${{ hashFiles('src/**', 'public/**') }}
          restore-keys: astro-${{ runner.os }}-
      - run: bun install --frozen-lockfile
      - run: npm run check                 # astro check on Node 26
      - run: npm run build
      - run: npm run test:smoke
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v4
        with:
          path: dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    timeout-minutes: 10
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

Details that fulfill the README contract: publishes on push to `main` + manual dispatch; `SITE_URL`/`BASE_PATH` overridable via repo **Variables**, defaulting to `https://eswr.github.io` / `/oca-medical-site`. `timeout-minutes: 10` per job prevents runaway minutes. Bun cache targets `~/.bun/install/cache` only (never `node_modules`), keyed on `bun.lock`.

### 5. `.gitignore`
Add `dist/`, `.astro/`, `.DS_Store` (currently only `node_modules`) so the first real commit doesn't include build artifacts.

### 6. `README.md`
Update for consistency: requirements line → Bun 1.4+ (install) + Node 26 (run Astro); lockfile instruction → commit `bun.lock` (replace the `package-lock.json`/`npm ci` line).
